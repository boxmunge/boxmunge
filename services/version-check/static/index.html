boxmunge

Minimalist, agent-friendly VPS hosting framework

boxmunge turns a fresh VPS into a hardened, production-ready Docker host. Deploy containerised projects with a single command, get automatic TLS, backups, health monitoring, and security updates out of the box.

GitHub repository

Install

pip install boxmunge
boxmunge server-setup you@your-server.example.com --email you@example.com

The CLI runs on your local machine and provisions the server over SSH.

Security updates & privacy

Every boxmunge server asks this service for updates every six hours, and again when its operator runs an upgrade, so it hears about security and break-fix releases quickly. The request carries the server's boxmunge version (in the address and in the User-Agent header) and, as with any connection, the server's IP address. No hostname, machine identifier or anything about the server's projects is sent. If an upgrade fails, the server also reports the version it tried, the version it came from, the step that failed and a short reason.

What this service stores:

  • For each update check: the network the request came from, cut down to a prefix (a /24 for IPv4, the first three numbers of the address; a /48 for IPv6), with the version and the date. Every server on one network shares that entry. These entries are deleted after 90 days.
  • For each failure report: the report, with the same network prefix. Reports are deleted after 90 days.
  • A daily count of checks per version.

Encrypted backups of the service's database can keep copies of these for longer than 90 days, until the backups themselves expire.

Your full IP address is never stored in the service's database. It is held in the service's memory to rate-limit requests, and it is written to two request logs.

Request logs: the web server in front of this service (Caddy) and the service itself each log every request, with the full IP address, the time, the URL requested (which includes the version) and the User-Agent. They are there for operations and abuse protection: the server's intrusion prevention (CrowdSec) reads the web server's log to block attackers. Both logs are rotated by size under Docker's log settings, up to five files of 50 MB each per log, the oldest discarded as new entries arrive; how long an entry lasts depends on traffic, not on a fixed number of days.

Why prefixes: boxmunge is in early beta, and its maintainer uses them to see which networks still run an old version and nudge those users to upgrade.

Opting out: boxmunge has no setting to turn version checks off. The scheduled check runs from the boxmunge-auto-update timer; stopping it (systemctl disable --now boxmunge-auto-update.timer) stops the scheduled checks, and with them automatic security updates and the alert when OS security updates stop arriving. Running an upgrade by hand still checks.

The source code for this service is open and auditable.
